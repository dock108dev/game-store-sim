# Ownership

This document maps runtime write ownership for the current single-owner
surfaces. The rows below are grounded in autoload registration, owner scripts,
and the validation scripts/tests that exercise those contracts.

## Matrix

| # | Responsibility | Owner (autoload / class) | Accepted callers | Forbidden patterns |
|---|---|---|---|---|
| 1 | **Scene load / transition** | `SceneRouter` autoload — sole caller of `get_tree().change_scene_to_file` / `change_scene_to_packed`. Tracks `_in_flight` to reject overlapping requests, awaits `tree_changed` + one `process_frame` after the engine queues the swap, then emits `scene_ready(target, payload)` and an `AuditLog.pass_check(&"scene_change_ok", …)` line. Failures emit `scene_failed(target, reason)` and `AuditLog.fail_check`. | `MainMenu` (new game), `GameManager` / `SceneTransition` paths that route through `SceneRouter`, and fatal-error UI ("return to menu"). Store entry in default hub mode is handled by `GameWorld` + `StoreDirector` in-tree injection rather than a viewport scene swap. | Direct `get_tree().change_scene_to_*` from UI buttons, gameplay, or modals. Two routers. `await create_timer` used as a sync primitive between transitions. |
| 2 | **Store lifecycle / ready declaration** | `StoreDirector` autoload drives `enter_store(store_id) → READY \| FAIL` through an explicit state machine (`IDLE → REQUESTED → LOADING_SCENE → INSTANTIATING → VERIFYING → READY/FAILED`); each transition emits an `AuditLog` checkpoint (`director_state_*`). The per-scene store controller (root script `game/scripts/stores/retro_games.gd`, extending the shared `game/scripts/stores/store_controller.gd`) executes the contract and reports outcome back; `StoreDirector` emits the final `store_ready` / `store_failed`. `StoreDirector` is the **sole** emitter of readiness to the rest of the game. | `SceneRouter` (after scene instantiated, or via `set_scene_injector` when a host scene like GameWorld hub mode wants in-tree injection instead of a full viewport swap), the store controller (reports outcome back to `StoreDirector`). Readers: `HUD`, `GameState`, `AuditLog`, `Day1ReadinessAudit`, `EventBus` subscribers. | UI or gameplay asserting "ready" on their own. Concurrent `enter_store` calls (state != IDLE). Partial-ready states ("scene up, camera pending"). Skipping any state. Re-emitting `store_ready` from a non-owner. |
| 3 | **Store content instantiation** | The per-store controller (per-store root). Instantiates shelves, props, and interactables under the store scene, registers them, and reports counts up. | Only the per-store controller itself, via its `_ready` and content builders. | Hub/world routing code or `SceneRouter` reaching into store content. Adding interactables at runtime from unrelated systems. Instantiating content before the controller has run. Placeholder nodes left in the tree and treated as "real" content. |
| 4 | **Camera authority** | `CameraAuthority` autoload. Tracks the single active camera through `request_current(cam, source)` (the only public write entry; `_make_current` and `_clear_others` are internal). Cameras are auto-added to the `cameras` group on first request, and `assert_single_active()` walks that group on every `store_ready`. | Store controller (requests store camera activation after content spawn), `GameWorld` / `MallHallway` camera setup, `MainMenu` (menu camera), cutscene/transition owners. | Setting `camera.current = true` directly from gameplay or UI. Two cameras both active. Cameras that never register with `CameraAuthority`. Changing the active camera during a transition's `VERIFYING` phase. |
| 5 | **Input focus / modal ownership** | `InputFocus` autoload. Stack of contexts. The constants defined in `game/autoload/input_focus.gd` are `CTX_MAIN_MENU` (`&"main_menu"`), `CTX_MALL_HUB` (`&"mall_hub"`), `CTX_STORE_GAMEPLAY` (`&"store_gameplay"`), `CTX_MODAL` (`&"modal"`). The topmost context wins. `CTX_STORE_GAMEPLAY` is owned by `StoreController` (pushed after `EventBus.store_entered`, popped on `store_exited`); per-store player avatars (`StorePlayerBody`) read the focus to gate input. `ModalQueue` (`game/autoload/modal_queue.gd`) is the current queued-modal coordinator: priority-ordered FIFO (`DAY_SUMMARY → VIC_NOTE → TUTORIAL → TOAST → PASSIVE_HUD`) that dispatches one queued `ModalPanel` at a time. Direct-open modal surfaces still pair their own `InputFocus.push_context(CTX_MODAL)` / `pop_context()` calls. `SceneRouter` calls `ModalQueue.clear()` before every scene swap. | `SceneRouter` (audits the focus stack on each `scene_ready`; clears `ModalQueue` before each swap), queued `ModalPanel` subclasses through `ModalQueue.request_open`, direct-open panel scripts with paired modal push/pop guards, and `StoreController` for store-gameplay focus. | `set_process_input` / `set_process_unhandled_input` called directly from scenes. Two systems both disabling input. Player bodies or unrelated gameplay code pushing `CTX_STORE_GAMEPLAY` themselves. Queued panels invoking `ModalQueue.notify_closed` / `cancel` directly from outside the panel lifecycle. Modals opened during a transition's `VERIFYING` phase. Empty focus stack after a transition. |
| 6 | **Run state (money, day, active store, flags)** | `GameState` autoload. Single source of truth for cross-scene run data. Mutations go through typed setters that emit signals. | `MainMenu` (reset on new game), `DayCycleController` (money/day writes on day close), `StoreDirector` (sets `active_store_id` on `store_ready`), save/load system. | Scenes storing their own copy of money/day. Direct field writes from UI. Mutating `GameState` during `VERIFYING` — run state must be written before or after ready, never mid-flight. |
| 7 | **Objective and HUD surfaces** | `ObjectiveDirector` owns objective payload emission/gating; `ObjectiveRail` renders the active objective payload outside store-session first-person mode; `StoreStatusPanel` renders store-session day status and passive milestone rows; `StoreEventLogPanel` renders store-session log lines; `InteractionPrompt` renders the bottom-right focused action affordance; `HUD` owns cash/time/reputation, live counter labels, and the first-person bottom sentence. | Systems emit `EventBus.objective_changed`, `objective_updated`, `store_session_objective_completed`, money/time/customer/store signals, or focused-interactable signals. Surface scripts read those signals and write only their own labels. | Store scripts calling HUD or rail setters directly. Active objective text duplicated across persistent HUD regions. Objective strings hardcoded in scene `.tscn` files. |
| 8 | **Store registry / id resolution** | `StoreRegistry` autoload. Maps `store_id: StringName` → scene path + metadata, seeded at `_ready` from `ContentRegistry`. `resolve(id)` fails loud on unknown ids. | `SceneRouter` / `StoreDirector.enter_store`, save/load (validates persisted ids). | Scene paths hardcoded in UI. `"res://..."` string literals for store scenes outside the registry. Silently returning `""` for an unknown id. |
| 9 | **Structured audit log** | `AuditLog` autoload owns structured `AUDIT: PASS <checkpoint>` / `AUDIT: FAIL <checkpoint>` output through `pass_check(checkpoint, detail)` and `fail_check(checkpoint, reason)`. `tests/audit_run.sh` accepts only this format. | Subsystems report structured checkpoints through `AuditLog`. | Legacy `[AUDIT] <key>: PASS\|FAIL` lines, ad-hoc `print` / `printraw` output pretending to be structured audit output, swallowing failures (`pass` emitted when an invariant actually failed), or parsing audit output outside `tests/audit_run.sh`. |
| 10 | **Cross-system eventing** | `EventBus` autoload is the central typed gameplay signal hub. Mirror signals over autoload-owned events include `store_ready(store_id)`, `store_failed(store_id, reason)`, `scene_ready(scene_name)` (single-arg mirror; the full `scene_ready(target, payload)` lives on `SceneRouter`), `run_state_changed()` (parameterless GameState mutation), `input_focus_changed(owner)`, and `camera_authority_changed(camera_path)`. Owner autoloads (`StoreDirector`, `SceneRouter`, `GameState`, `InputFocus`, `CameraAuthority`) remain the authoritative emitters; direct owner APIs are still used for command-style operations. | Any system may listen. Emitters should be the owner of the event being mirrored or broadcast. | Using `EventBus` to bypass an owner above (for example, emitting `store_ready` from a non-`StoreDirector` path). Adding gameplay logic or cached state to `event_bus.gd` beyond signal declarations and thin emit helpers. |
