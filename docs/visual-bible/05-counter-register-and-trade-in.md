# Counter, Register, And Trade-In

Status: Active visual bible
Spreadsheet families: Counter, Electronics checkout, storage/counter rows, paper goods
Primary IDs: OBJ-026 through OBJ-039, OBJ-047, OBJ-048

## Target Read

The counter should read as a real small game-store checkout and trade-in station. It should not become a clutter shrine, and it should not rely on floating labels. The day-one state is mostly empty and operational: register, scanner, cash drawer, bags, straight counter, and one shared checkout/trade-in workflow.

## Locked Decisions

- Use a straight counter.
- Checkout and trade-in share the same station.
- Register area should be visually selected for composition, not debated further.
- Counter and register need the same level of detail as products.
- Behind-counter area is mostly empty day one.
- Future employee/second-register expansion can happen later.

## Counter Mesh Requirements

The counter should include:

- real counter depth and height
- toe-kick/base
- laminate top with edge trim
- front panel material break
- under-counter cabinet or open negative space
- clean player-side/customer-side read
- collision separate from visual mesh

Do not build it as a black block with a pale slab.

## Register Detail Requirements

MVP POS/register cluster should include:

- screen with subtle inactive/idle display
- keypad or button surface
- scanner cradle
- receipt printer
- cash drawer implied by counter or register base
- bags/paper stack optional

The screen can use a static texture; it does not need a full UI in-world for MVP.

## Trade-In Visual Requirements

Trade-in should be readable through:

- inspection pad
- clean intake space
- one small tote/box or sleeve box
- scanner/magnifier/clipboard later

Avoid making the counter look like a pawn-shop junk pile on day one.
